# CLAUDE.md — `startupweekendnantes.fr/` (Astro rewrite)

Astro 5 + React 19 + TypeScript. Static output (no SSR). All assets local — `framerusercontent.com` and any external CDN URLs are forbidden.

Don't use worktrees for this directory.

## Structure

- `src/pages/index.astro` — single page, imports and assembles all section components.
- `src/pages/404.astro` — not-found page.
- `src/pages/llms.txt.ts` — Astro endpoint that prerenders `/llms.txt` (a plain-text, AI-citable digest of the event) from the `src/data/` modules. Rolls over with the edition automatically.
- `src/layouts/Layout.astro` — head/meta/GTM/fonts + SEO (canonical, `robots`, geo-targeting meta `author`/`geo.region`/`geo.placename`/`ICBM`, Open Graph, Twitter Card, JSON-LD) + motion animations (via `motion` package). Accepts `title`/`description`/`robots` props (`robots` defaults to `index, follow`; 404 passes `noindex, follow`). The homepage JSON-LD (`buildHomeJsonLd()`) is wired internally, gated on `Astro.url.pathname === '/'` — not passed as a prop.
- `src/components/*.tsx` — one component per section, paired with `<Component>.css`.
- `src/components/Picture.tsx` — shared image helper: renders `<picture>` with auto `avif`/`webp` `<source>`s and `width`/`height` (CLS) from `src/data/image-manifest.ts` (uses `display: contents`, so it adds no layout box). Use it for content images; decorative CSS backgrounds (Hero/Welcome) and the preloaded LCP image stay as plain `<img>`.
- `src/data/image-manifest.ts` — AUTO-GENERATED by `scripts/optimize-images.mjs` (image path → intrinsic `width`/`height` and which modern formats `avif`/`webp` exist). Do not edit by hand; excluded from eslint. Regenerate it (`node scripts/optimize-images.mjs`) whenever images are added directly to `public/assets/images/` without going through the script — a stale manifest silently serves unoptimised originals with no `<source>`s and no CLS-safe dimensions.
- `src/data/*.ts` — all content data (see "Data lives in `src/data/`" below).
- `src/data/meta.ts` — schema.org JSON-LD builder (`buildHomeJsonLd()` → Event/FAQPage/Organization/WebSite/VideoObject×N/Place/BreadcrumbList) assembled from the other data modules. Event carries `inLanguage`, an `ImageObject`, offer `priceValidUntil`, and `speakable`; Place carries an `@id` and `geo` GeoCoordinates (approx — verify the venue lat/long); Organization carries `address`/`email`/`contactPoint` (NaoMakers, the organising entity per the Billetweb listing) and `sameAs`; one `VideoObject` per `past.ts` recap video (`uploadDate`/`duration` intentionally omitted — not verified, and a fabricated value is worse than a missing one for Google's rich-result checks).
- `src/data/videos.ts` — past editions' recap videos (keyed by year), shown on the homepage by `PastGlimpse`. Frozen history; never derives from `EDITION`.
- `src/styles/global.css` — base styles, CSS custom properties, `@font-face` declarations. Cal Sans / Funnel Display / Instrument Sans are self-hosted as subset WOFF2 (`public/fonts/`, see below); Space Mono is the one exception, loaded from Google Fonts via a `<link>` in `Layout.astro`'s `<head>` — never `@import` it here (an `@import` blocks CSS parsing until it resolves; a `<link>` lets the browser fetch it in parallel).
- `public/assets/images/` — all images, sorted into per-section folders (`speakers/`, `orga/`, `sponsors/`, `venue/`, `intro/`, `hero/`, `welcome/`, `pricing/`, `brand/`, `og/`). Profile pictures are named after the person (e.g. `speakers/thomas-matthieu.jpeg`). Served at `/assets/images/<folder>/<name>`.
- `public/assets/images/og/og-cover.jpg` — Open Graph share image (1200×630), regenerable via `node scripts/generate-og-image.mjs`.
- `public/robots.txt` — allows all, references `sitemap-index.xml`, and explicitly allows the major AI answer-engine crawlers (`GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `PerplexityBot`, `Google-Extended`, `Applebot-Extended`) — called out by name rather than relying on the blanket `Allow: /`, since the site wants to be cited. The AI digest is served at `/llms.txt` (generated by `src/pages/llms.txt.ts`, not a static file; also linked from `Layout.astro`'s `<head>` via `<link rel="alternate" type="text/plain">`).
- `scripts/generate-og-image.mjs` — one-off `sharp` script that builds the OG image from the hero cut-out (not part of the build).
- `scripts/optimize-images.mjs` — one-off `sharp` script (not part of the build): resizes/recompresses every raster in `public/assets/images/` in place (max 2000px), emits `.webp`/`.avif` siblings (kept only when smaller than the fallback), and regenerates `src/data/image-manifest.ts` with each image's intrinsic `width`/`height` plus which modern formats exist. Run it after adding/replacing images — new images dropped straight into `public/assets/images/` without running this are served as unoptimised originals with no CLS-safe dimensions.
- `public/fonts/*.woff2` — self-hosted font files (Cal Sans, Funnel Display, Instrument Sans), subset to the Latin range this French-language site needs (incl. `€`, «», –—…) via `pyftsubset` (requires `pip install brotli` for the WOFF2 encoder):
  ```bash
  pyftsubset <Font>.ttf --output-file=<Font>.woff2 --flavor=woff2 \
    --unicodes="U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+2000-206F,U+2074,U+20AC,U+2122,U+2191,U+2193,U+2212,U+2215,U+FEFF,U+FFFD" \
    --layout-features='*' --no-hinting
  ```
  Regenerate only when a font file changes; commit the `.woff2`, not the source `.ttf`.
- `tests/visual.spec.ts`, `tests/compare.spec.ts` — Playwright visual regression (legacy vs astro, all sections).
- `astro.config.mjs` — `site`, dev port `4323`, React + sitemap integrations, React dedupe (forces a single React copy so `motion` doesn't bundle its own).
- `vercel.json` — build config for Vercel + security response headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`) + immutable `Cache-Control` for `/assets/*` and `/fonts/*`.


## Coding conventions

### Data lives in `src/data/`

Content data is **never** inlined in components — it lives in dedicated modules under `src/data/`, typed and exported, then imported by the matching component. When a component renders the same HTML block multiple times with different data (team, FAQ, sponsors, agenda rows…), the data array goes in `src/data/`, the component imports it and loops once. Never repeat JSX blocks.

```tsx
// src/data/edition_speakers.ts
export type Speaker = { name: string; role: string; img: string };
export const speakers: Speaker[] = [
  { name: 'Thomas Matthieu', role: 'CEO @ Guest Suite', img: '/assets/images/speakers/thomas-matthieu.jpeg' },
];

// src/components/Team.tsx
import { speakers } from '../data/edition_speakers';
speakers.map(s => (
  <div key={s.name} className="member-card">
    <img src={s.img} alt={s.name} />
    <h3>{s.name}</h3>
    <p>{s.role}</p>
  </div>
));
```

Modules whose content changes every year carry the `edition_` prefix (`edition.ts`, `edition_speakers.ts`, `edition_partners.ts`, `edition_pricing.ts`, `edition_schedule.ts`); stable data does not (`faq.ts`, `team.ts`, `venue.ts`, `videos.ts`, `site.ts`).

### `edition.ts` is the single source of truth

`src/data/edition.ts` exports `EDITION` — year, dates (incl. `startISO`/`endISO` for the Event schema), ticket URL, contact email, derived date strings and pre-built agenda day headers. Hero `<h1>`, Footer ©, Agenda labels, SEO meta, JSON-LD and the ticket link are all derived from it. **To roll the site over to a new year, edit `edition.ts` (and the other `edition_*` data files) only** — never hardcode a date or year in a component.

### `site.ts` holds stable site/SEO metadata

`src/data/site.ts` exports `SITE` — site name, canonical URL, `lang`, theme color, GTM container id, favicon/icon/manifest paths, OG/social fields (`locale`, `ogImage`/`ogImageWidth`/`ogImageHeight`/`ogImageAlt`, `organizerName`, `logo`), and the default `<title>`/description templates (themselves derived from `EDITION`). It feeds the `Layout.astro` `<head>` (meta tags, OG/Twitter, GTM snippet) and `astro.config.mjs` (`site: SITE.url`). Both `site.ts` and `edition.ts` are sources of truth consumed by `astro.config.mjs`. Never hardcode a meta tag, GTM id or the site URL in a component or in the config.

### SEO / structured data

`Layout.astro` emits the canonical link, `robots` (overridable via the `robots` prop — see 404.astro), geo-targeting meta (`author`/`geo.region`/`geo.placename`/`ICBM`), Open Graph + Twitter Card tags, and a JSON-LD `<script>` on the homepage only (`buildHomeJsonLd()`, gated on `Astro.url.pathname === '/'`, not a prop). Structured data is built in `src/data/meta.ts` from the existing content modules (no duplication). `SITE.ogImage` currently points at a stopgap photo (`amb-foule.jpg`, wrong aspect ratio for OG); a properly sized 1200×630 banner exists at `public/assets/images/og/og-cover.jpg` (regenerable with `node scripts/generate-og-image.mjs`) but it composites the *2025* hero cut-out — regenerate it from the 2026 hero art (or design a new banner) before pointing `SITE.ogImage` back at it. Canonical/sitemap URLs are normalised without trailing slashes (except root) to match Vercel's `trailingSlash: false`.

For AI / generative-engine optimisation (GEO): `/llms.txt` exposes a plain-text, citable digest of the event (generated by `src/pages/llms.txt.ts` from `src/data/`), the Event/FAQPage JSON-LD carry `speakable`, and the FAQ answers are always rendered in the DOM (`hidden` when collapsed) so search/AI crawlers see the answer text, not just the JSON-LD.

### Styling: CSS per component

No Tailwind, no CSS-in-JS. Each component has its own `<Component>.css` file (e.g. `Hero.tsx` ↔ `Hero.css`). Shared variables and base styles live in `src/styles/global.css`.

Inline `style={...}` only for values that come from runtime data (e.g. dynamic colors from a data array). Static styles always go in `.css`.

### Assets

All images served from `/assets/images/`, organised into per-section folders
(`speakers/`, `orga/`, `sponsors/`, `venue/`, `intro/`, `hero/`, `welcome/`,
`pricing/`, `brand/`). Profile pictures are named after the person. To add a new image:
1. Drop the file in the relevant `public/assets/images/<section>/` folder.
2. Reference it (via the `Picture` component for content images, so it gets avif/webp + dimensions).
3. Run `node scripts/optimize-images.mjs` to compress it and generate the modern-format siblings + manifest entry.

Never link to `framerusercontent.com` or any external CDN.

### Hydration

Components are static by default. Use `client:load` / `client:visible` on Astro side only for components with state or interactivity: `<Hero client:load />` (countdown timer), `<FAQ client:load />`, `<PastGlimpse client:visible />` (click-to-play YouTube facade — `client:visible` since it's a below-the-fold perf win, not needed for first paint).
